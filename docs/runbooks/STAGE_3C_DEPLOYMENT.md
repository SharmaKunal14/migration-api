# Stage 3C deployment

Stage 3C adds an immutable Change Intelligence Agent image, a control Lambda,
database migration, Fargate task, and operator-started Step Functions workflow.
It has no public API or UI control.

## 1. Create the dedicated OpenAI identity

Create a separate OpenAI service account and AWS workload-identity provider for
the change-intelligence task role:

```text
arn:aws:iam::393209814365:role/migration-api-development-change-intelligence-task
```

Add these non-secret variables to the protected GitHub `development`
environment:

```text
CHANGE_INTELLIGENCE_OPENAI_IDENTITY_PROVIDER_ID
CHANGE_INTELLIGENCE_OPENAI_SERVICE_ACCOUNT_ID
```

Do not reuse an API key or store one in GitHub, Terraform, ECS, or Lambda.

## 2. Apply the container foundation

Use Terraform 1.15.8 and inspect the saved plan:

```bash
terraform -chdir=infra/terraform/foundation plan \
  -input=false \
  -var="aws_region=ap-southeast-2" \
  -var="owner=KunalSharma" \
  -out=stage-3c-foundation.tfplan
terraform -chdir=infra/terraform/foundation show \
  -no-color \
  stage-3c-foundation.tfplan
```

The plan should add only the
`migration-api-development-change-intelligence-agent` ECR repository and its
lifecycle policy. Investigate unrelated replacement or destruction, then
apply:

```bash
terraform -chdir=infra/terraform/foundation apply \
  -input=false \
  stage-3c-foundation.tfplan
```

## 3. Run the protected development deployment

Commit and push the Stage 3C revision, then run **Deploy development** with
confirmation `deploy-development`. The workflow builds and scans the new
image, runs migration `0006_stage_3c.sql`, pauses for protected-environment
approval, and applies the exact saved plan.

Confirm that the task role has only:

- read access to `env/development/vendor/*`;
- write access to `env/development/change-intelligence/*`;
- use of the exact artifact KMS key;
- conditioned `sts:GetWebIdentityToken`.

It must not have Secrets Manager, database, GitHub, Lambda invocation, or
general S3 permissions.

## 4. Generate the OrbitChat draft

```bash
change_intelligence_arn="$(
  terraform -chdir=infra/terraform/environments/development \
    output -raw change_intelligence_state_machine_arn
)"
correlation_id="$(uuidgen | tr '[:upper:]' '[:lower:]')"
aws stepfunctions start-execution \
  --region ap-southeast-2 \
  --state-machine-arn "${change_intelligence_arn}" \
  --name "orbitchat-spec-${correlation_id}" \
  --input "$(
    jq -cn \
      --arg release_id "914e7575-7dc8-40e4-9445-aa61bfdb4ade" \
      --arg correlation_id "${correlation_id}" \
      '{
        schemaVersion: "1.0",
        vendorReleaseId: $release_id,
        correlationId: $correlation_id
      }'
  )"
```

## 5. Verify the outcome

The Step Functions execution should be `SUCCEEDED`. In the Supabase SQL editor:

```sql
select
  status,
  attempt,
  safe_error_code,
  model_calls,
  tool_calls,
  iterations,
  migration_specification_id,
  completed_at
from change_intelligence_runs
where vendor_release_id = '914e7575-7dc8-40e4-9445-aa61bfdb4ade';

select
  source_compatibility,
  target_version,
  trust_state,
  revision,
  generated_by,
  reviewed_by_user_id,
  reviewed_at,
  specification
from migration_specifications
where vendor_release_id = '914e7575-7dc8-40e4-9445-aa61bfdb4ade'
order by revision desc;
```

Expected values:

- run status `succeeded`;
- a non-null specification ID;
- source compatibility `1.x` and target `2.0.0`;
- trust state `draft`;
- generated by `change_intelligence_agent`;
- reviewer and review timestamp both null;
- seven changes plus an uncertainty for notification defaults.

Starting the workflow again for the same evidence returns successfully without
creating a second specification.

## Failure handling

The workflow fails closed for a stale or altered evidence manifest, unregistered
source, digest mismatch, model/tool/token budget exhaustion, invalid model
output, false trust claims, or unsupported evidence references. Fix the
underlying cause and start another execution. Attempts are capped at ten; a
running attempt is recoverable after twenty minutes.
